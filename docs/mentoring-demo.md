# CLUE 1차 멘토링 시연

CLUE는 강의 화면과 시스템 오디오를 수집합니다. 사용자가 강의 내용에 질문하면 관련 화면과
전사를 찾아 답변을 스트리밍합니다.

이 데모는 `integration e55997e`의 데스크톱 UI를 기준으로 합니다. 프레임은
`frame-processing ef28d07`의 테스트와 GPU 수정 커밋 `87f70f2`, RAG는
`audio_processing b920948`의 문장 청킹, 맥락은 `feat/context-qa def2e08`의 재생 도구와
테스트를 사용합니다. `desktop_app 4cdc5a9`의 변경은 이미 통합 기준 커밋에 포함되어 있습니다.

## 시작 전

1. Windows x64에 Python 3.12를 준비합니다. 프로젝트 루트에서 설치를 한 번 실행합니다. GPU를 쓸 수 있는지는 앱이 실제 워밍업으로 확인합니다.
2. 앱의 톱니바퀴를 열어 **OpenAI API 키 설정**에서 키를 저장합니다. 첫 질문을 보낼 때에도 미설정 키 입력 화면이 열립니다. 질문에 관련된 이미지와 전사가 OpenAI 요청에 포함되므로 사용 허가를 받은 자료를 선택합니다.
3. 30초 이상 설명이 이어지고 화면에서 주제가 표시되는 구간을 고릅니다. NVIDIA GPU가 없는 환경의 기본값도 확인하려면 아래 진단에서 CPU 전사 결과를 확인합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-demo.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-demo.ps1 -Diagnose
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-demo.ps1
```

## 시연 순서

| 단계 | 시연 화면과 확인 사항 |
| --- | --- |
| 강의 선택 | 강의 플레이어의 창이나 강의 영상 영역을 고릅니다. 앱은 Windows 기본 출력 장치에서 시스템 소리를 받습니다. |
| 수집 시작 | GPU 또는 CPU 선택 메시지를 확인합니다. 영상을 재생하고 대표 화면 미리보기가 바뀌는지 확인합니다. |
| 질문 | 강의 주제가 바뀐 뒤 앞부분의 설명을 질문합니다. 답변에서 실제 강의의 용어나 그림 내용이 사용됐는지 확인합니다. |
| 세션 종료 | 잠시 일시정지하고 재개한 뒤 정지합니다. 이전 대표 프레임과 세션 DB가 남는지 확인합니다. |

별도 강의가 준비되지 않았을 때는 팀이 직접 읽고 녹음할 수 있는 다음 짧은 강의를 사용합니다.
첫 장에는 **캐시와 원본 저장소**, 다음 장에는 **캐시 미스와 TTL**을 표시합니다.

> 캐시는 반복 조회를 빠르게 처리합니다. 캐시에 없는 요청은 원본 저장소로 전달합니다.
> 저장소에서 가져온 값은 캐시에 잠시 저장할 수 있습니다. 만료 시간을 설정하면 오래된 값이
> 계속 제공되는 것을 줄일 수 있습니다. 캐시가 빨라도 원본의 정확한 값은 원본 저장소가 관리합니다.

- 첫 질문은 “캐시에 값이 없으면 어디에서 가져오나요?”를 사용할 수 있습니다.
- 이어서 “만료 시간을 두는 이유를 방금 설명과 연결해 주세요”로 앞서 수집한 강의 내용을 확인합니다.
- 진단과 워밍업을 시연 전에 한 번 실행합니다. 키 없이 화면 흐름을 확인하는 개발 테스트는 로컬 `.env`에서 `CLUE_FAKE_LLM=1`로 활성화할 수 있습니다.

## 전달 파일과 권장 환경

릴리스 브랜치의 소스와 이 진행서를 전달합니다. 설치와 실행에 필요한 파일은
`scripts/setup-demo.ps1`, `scripts/run-demo.ps1`, `scripts/prepare_demo_models.py`,
`requirements-*-win-py312.txt`입니다. 받는 PC에서 설치 스크립트가 가상환경과 모델을
준비합니다. `.env`, 로컬 가상환경, 모델 캐시, 강의 영상과 세션은 각 PC에서 관리합니다.

시연 준비 기준으로 Windows x64, Python 3.12 x64, RAM 16GB와 여유 저장 공간 15GB를
권장합니다. 실기 검증 GPU는 RTX 4060 Ti 8GB입니다. GPU 워밍업이 실패하면 앱이 CPU
호환 모드를 안내합니다. 설치와 실제 GPT 호출에는 인터넷 연결이 필요합니다.

## 문제가 생겼을 때

| 증상 | 확인 방법 |
| --- | --- |
| CPU 모드로 실행 | `run-demo.ps1 -Diagnose`로 CUDA 워밍업 결과와 원인을 확인합니다. NVIDIA 사용을 원하면 설치된 드라이버와 가용 VRAM을 확인합니다. |
| 모델 누락 또는 다운로드 실패 | [모델 준비 재시도](../INSTALL-dependencies-win-py312.md#설치)를 실행한 뒤 진단에서 준비 결과를 확인합니다. |
| API 키·권한 또는 인터넷 오류 | 대화창의 메시지를 확인하고 설정에서 키를 교체하거나 연결을 복구한 뒤 질문을 다시 보냅니다. |
| 창 종료 또는 음성 장치 오류 | 선택한 창을 다시 열고 다시 선택합니다. 음성은 Windows 기본 출력 장치를 확인합니다. 자동 모드는 화면 질의응답을 이어갈 수 있습니다. |

앱을 실행한 PowerShell에는 모듈 진단과 실패 원인이 남습니다. 질문과 대표 프레임의 저장
상태는 `sessions/<session_id>/metadata.db`와 `frames/`에서 확인할 수 있습니다.

실제 OpenAI API 스트리밍은 유효한 키가 갖춰진 환경에서 확인해야 합니다. 기본 응답 경로는
실제 API이며 자동 테스트와 로컬 검증에서는 응답을 대신하는 테스트 코드를 사용했습니다.

### 다른 PC에서 재검증

1. 기본 설정으로 설치한 뒤 `run-demo.ps1 -Diagnose`를 실행합니다. NVIDIA에서는 드라이버·CUDA 호환성, 여유 VRAM, Paddle과 Whisper 워밍업을 확인합니다. AMD·Intel·CPU 전용 PC에서는 CPU 모드 안내와 `base` 전사 결과를 확인합니다.
2. 강의 창과 화면 영역을 각각 선택해 수집합니다. 음성과 화면의 시점, 대표 화면, 일시정지·재개·정지를 확인합니다. GPU 장시간 재검증에는 강의를 15분 이상 재생합니다.
3. 허가된 시연 자료를 사용해 현재 화면, 방금 설명, 과거 설명을 차례로 질문한 뒤 이전 답변에 후속 질문을 합니다. 설정 화면에서 사용할 키를 저장하고 답변이 스트리밍되는지 확인합니다.
4. 세션 정지 후 프로젝트 루트에서 아래 명령으로 SQLite 무결성을 확인합니다. `SESSION_ID`는 확인할 세션의 폴더명으로 바꿉니다.

```powershell
& .\.venv312\Scripts\python.exe -m sqlite3 .\sessions\SESSION_ID\metadata.db 'PRAGMA integrity_check;'
```
